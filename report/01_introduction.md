# CHAPTER 1 INTRODUCTION

## 1.1 Overview of the Project Domain

The emergence of large language models has significantly changed the way users expect to interact with digital information systems. Instead of navigating folders, portals, PDF files, and administrative webpages manually, users increasingly prefer to ask direct natural language questions and receive concise, contextually relevant answers. This expectation is particularly visible in academic institutions, where students, faculty members, coordinators, and administrative staff frequently need access to diverse forms of information such as course structures, attendance rules, seminar procedures, syllabus details, project formats, departmental roles, and institutional regulations. However, the underlying knowledge sources within an academic environment are not uniform. Some information is inherently structured, such as which faculty member belongs to which department or which course is taught by which instructor, while other information is document-centric and appears only inside handbooks, circulars, guidelines, or PDF attachments. The project domain of this report therefore lies at the intersection of academic information systems, information retrieval, knowledge representation, and local-first conversational artificial intelligence.

Retrieval-Augmented Generation, commonly abbreviated as RAG, has emerged as an influential approach for grounding language model outputs in external evidence rather than relying only on parametric memory inside the model itself (Lewis et al., 2020). In a typical RAG pipeline, a user query is converted into a representation suitable for information retrieval, relevant passages are retrieved from a knowledge source, and a generative model then uses the retrieved context to produce an answer. The advantage of this approach is that it can reduce hallucination, improve factuality, and support dynamic updating of knowledge without retraining the generator. For institutional question answering, this property is highly desirable because academic rules and document collections change over time, and a static language model cannot be assumed to always store the most recent or institution-specific information.

At the same time, unstructured retrieval alone is often insufficient in academic settings. Many institutional queries depend not only on descriptive text but also on relationships among entities. For example, a question such as "Who teaches Computer Graphics?" involves a relation between a faculty entity and a course entity. A question like "Which department does this faculty member belong to?" requires entity linking and structural reasoning. Knowledge graphs are especially useful in such situations because they model entities, properties, and relationships in an explicit machine-readable format, allowing factual lookups and interpretable graph-based querying (Hogan et al., 2021). RDF and SPARQL based graph systems are therefore relevant to question answering tasks that demand precision over connected institutional data rather than similarity over text alone.

The project described in this report, named **NexRag**, addresses this blended requirement by integrating a knowledge graph, a document retrieval pipeline, and a local language model. It is not merely a chatbot interface placed over a set of files. Instead, it is a hybrid academic assistant that combines multiple evidence pathways and uses a routing mechanism to determine how each query should be handled. The implementation available in the repository shows a backend built with FastAPI, a frontend built using React and Vite, a knowledge graph served through Apache Jena Fuseki, document retrieval supported by FAISS, BM25, and cross-encoder reranking, and a locally hosted language model accessed via Ollama. This combination positions the project in a modern and practically relevant domain: grounded academic conversational systems that aim for transparency, extensibility, and offline-friendly deployment.

The domain is also important because it reflects a broader engineering transition from monolithic information systems toward composable intelligence pipelines. Recent surveys note that RAG systems are becoming foundational for trustworthy human-AI interaction, particularly when accurate access to enterprise or organizational knowledge is more important than open-ended creativity (Gao et al., 2023). In education, institutional knowledge is fragmented across regulations, semester handbooks, curriculum documents, notices, and departmental records. A well-designed hybrid assistant can reduce search friction, improve accessibility, and provide traceable answers. Consequently, the project belongs to an academically meaningful and technically current domain with direct societal relevance.

## 1.2 Background and Importance

Traditional academic information access generally follows a document-first approach. Students may browse PDF handbooks, semester guidelines, course files, seminar instructions, and departmental notices to extract answers manually. This process is time consuming and often frustrating because the same type of question may require looking across multiple sources. Even when institutional data is technically available, its discoverability remains weak. Search within PDFs may fail due to terminology mismatch, and users often do not know which document contains the answer. As a result, routine academic questions generate repeated communication overhead for faculty and administrators.

Early chatbot systems attempted to automate such interactions using rule-based or FAQ-style designs. While simple to deploy, those systems were usually narrow, brittle, and difficult to maintain. They performed well only when the wording of the user query matched the expected pattern. More advanced natural language systems improved interaction quality, but if they relied solely on pretrained language models, they introduced a new concern: the possibility of generating plausible sounding yet incorrect answers. This issue is especially serious in academic settings because misinformation about regulations, evaluation criteria, or course requirements can have direct consequences for students. The move toward retrieval-augmented systems emerged partly as a response to this challenge, allowing answers to be grounded in retrieved evidence rather than generated from unsupported model memory (Lewis et al., 2020; Gao et al., 2023).

Dense retrieval research has shown that embedding-based methods can outperform traditional sparse retrieval on many knowledge-intensive question answering tasks by learning semantic representations of queries and passages (Karpukhin et al., 2020). Sentence-level embedding models, such as Sentence-BERT, further improved the practicality of semantic search by making sentence representation efficient enough for large-scale similarity comparisons (Reimers and Gurevych, 2019). Vector search systems such as FAISS then enabled scalable similarity indexing and fast nearest-neighbour retrieval even when the document collection grows substantially (Johnson, Douze and Jegou, 2017). These developments make it feasible to build responsive retrieval systems for campus documents and academic guidelines.

Yet semantic retrieval has its own limitations. Dense models can retrieve topically related passages that are semantically close but not necessarily authoritative or specific enough for policy interpretation. Lexical methods such as BM25 remain valuable because exact terminology often matters in academic regulations. For example, terms like "condonation", "attendance", "credit requirement", or "seminar abstract" may appear in formal documents and should influence ranking strongly. The probabilistic relevance framework underlying BM25 continues to be a strong baseline for text retrieval because it captures lexical salience in a principled way (Robertson and Zaragoza, 2009). Modern hybrid systems therefore often combine dense and sparse retrieval before applying a more precise reranking stage.

Reranking is another important background concept. First-stage retrieval must be broad enough to recall relevant candidates, but final answer quality depends on selecting the best supporting passages from that candidate set. Cross-encoder rerankers, particularly those derived from BERT, have shown strong passage ranking performance because they model query-document interaction jointly rather than independently embedding each component (Nogueira and Cho, 2019). Although this is computationally heavier than first-stage retrieval, it is highly effective when applied only to a small set of candidates. In practical systems, a cascade combining recall-oriented retrieval with precision-oriented reranking is often superior to either step alone.

Knowledge graph technology contributes a different but complementary strength. In a knowledge graph, institutional entities such as faculty, departments, courses, and regulations can be represented as RDF resources connected through explicit predicates. Such a representation is particularly useful when queries require relationship resolution, controlled vocabulary, or structured browsing. Comprehensive work on knowledge graphs emphasizes that their value lies not only in storing facts, but in explicitly preserving semantics and enabling interoperable querying across related entities (Hogan et al., 2021). In the context of academic assistants, this can improve interpretability and reduce ambiguity for questions involving assignments of responsibility, course-faculty mappings, or departmental hierarchy.

The importance of a local-first design adds another practical dimension. Many contemporary AI assistants rely on remote commercial APIs, which may raise concerns around privacy, cost, internet dependence, rate limits, and institutional data governance. A local-first architecture attempts to preserve control by keeping the language model, retrieval indexes, and graph services within the local deployment environment. This is particularly relevant for educational institutions that may prefer on-premise or low-cost deployments and wish to avoid sending internal documents to external services. The repository for NexRag reflects this concern by integrating a local Ollama-served model, local FAISS index files, and a locally hosted Fuseki knowledge graph, thereby making the architecture aligned with deployment realities in constrained or privacy-sensitive settings.

The project is therefore important at multiple levels. At the user level, it aims to reduce information access friction. At the institutional level, it promotes traceable and controllable academic information services. At the technical level, it demonstrates how structured and unstructured evidence sources can be combined inside a coherent question answering pipeline. At the educational level, it offers a realistic final year project that integrates software engineering, natural language processing, information retrieval, semantic web technologies, and frontend-backend system design into a single end-to-end application.

## 1.3 Motivation

The primary motivation for developing NexRag arises from the observation that institutional knowledge is simultaneously abundant and inaccessible. Students often face simple but high-impact questions such as the attendance threshold for examination eligibility, seminar formatting rules, project report requirements, or the faculty associated with a course. These questions should ideally be answerable immediately and accurately. In practice, users must search across multiple documents, interpret administrative phrasing, or contact faculty members for clarifications. This creates unnecessary delay and duplicates communication effort across the institution.

Another motivation comes from the limitations of generic conversational AI tools. While large language models are capable of fluent dialogue, they are not automatically reliable sources of institution-specific knowledge. Without grounding, they may answer based on general educational norms rather than the actual rules of the institution. This is unacceptable in a system intended for academic use. The motivation was therefore not merely to build a chatbot, but to build a grounded assistant that derives answers from explicit institutional evidence. Such a design demands a retrieval layer, evidence presentation, and a mechanism to prefer known facts over speculation.

There is also a strong technical motivation to integrate multiple knowledge modalities rather than choosing one in isolation. Pure document retrieval is useful for explanatory content but weak for entity relations. Pure knowledge graph querying is precise for facts but limited when richer textual explanation is needed. A hybrid system promises better coverage than either approach alone. For example, if a user asks who teaches a course, the knowledge graph can provide a direct answer. If the user asks about report formatting or seminar expectations, the PDF collection may contain the necessary guidance. If a query touches both structure and explanation, a combined answer can potentially provide graph facts and document evidence together. This layered reasoning capability motivated the architectural choice behind NexRag.

The repository further reveals a motivation toward usability and transparency. The frontend does not simply display an answer. It includes route labels, confidence indicators, retrieved source references, system status panels, and a knowledge graph editor. These interface elements indicate that the project aims to make internal system behavior partially visible to users rather than presenting AI output as a black box. Such visibility is especially important in academic contexts where users may want to verify whether an answer came from the knowledge graph, from retrieved documents, or from a fallback mode with limited evidence.

From a project engineering perspective, the work is motivated by the desire to build a modern full-stack AI application that is not merely experimental but operational. The codebase includes startup automation, test scripts, evaluation tooling, health checks, frontend components, graph maintenance flows, and logging facilities. This suggests an intention to move beyond proof-of-concept demonstrations toward a deployable academic assistant. For a final year B.Tech project, this is valuable because it demonstrates software lifecycle awareness in addition to algorithmic implementation.

Finally, the project is motivated by the educational value of bringing together several advanced topics in a unified application. Students implementing such a system must understand data ingestion, text chunking, embedding generation, vector indexing, hybrid search, neural reranking, RDF graph modeling, SPARQL querying, API design, frontend rendering, streaming responses, and system evaluation. The project therefore provides not only a useful software product but also a strong learning platform for applied artificial intelligence and software systems engineering.

## 1.4 Problem Statement

Academic institutions store important information in heterogeneous forms such as PDF handbooks, syllabus files, seminar instructions, regulations, and departmental records. Users seeking answers to academic queries often face difficulty locating the correct source, identifying the relevant passage, and determining whether the retrieved information is current and authoritative. Existing general-purpose chatbots are unable to guarantee institution-specific factual accuracy, while traditional search systems lack conversational interaction and often fail to capture semantic intent. In addition, questions involving relationships among institutional entities, such as faculty-course mappings or departmental associations, are not easily handled by unstructured retrieval alone.

The problem addressed in this project is therefore to design and implement a local-first academic assistant that can answer institutional academic queries accurately, transparently, and efficiently by combining structured knowledge graph reasoning with unstructured document retrieval and grounded language generation. The system must support multiple query types, expose evidence to the user, remain extensible for new documents and graph updates, and operate without dependence on cloud-hosted proprietary intelligence services.

More specifically, the problem can be decomposed into the following technical subproblems. First, the system must determine how to route a user query, since not every question should be handled by the same retrieval path. Second, it must extract useful information from PDF documents and convert it into a searchable representation. Third, it must maintain a machine-readable knowledge graph for structured queries. Fourth, it must combine retrieval outputs and graph facts in a way that supports coherent response generation. Fifth, it must present the answer along with enough transparency for the user to judge its grounding. Solving these subproblems in a coordinated manner forms the central engineering objective of NexRag.

## 1.5 Challenges in Existing Systems

Several challenges in existing systems justify the need for the proposed work. The first challenge is **fragmentation of academic knowledge sources**. Academic information is rarely centralized in a single normalized database. Instead, it is distributed across curriculum files, circulars, project guidelines, handbook rules, and departmental information records. A user-facing system must therefore deal with content heterogeneity and cannot assume uniform structure across all inputs.

The second challenge is **hallucination and unsupported generation**. Large language models can generate fluent answers even when evidence is missing, which makes them risky in fact-sensitive domains. Recent work on RAG and its evaluation emphasizes that grounding and faithfulness are crucial when building reliable question answering systems (Lewis et al., 2020; Es et al., 2024). Academic assistants require explicit evidence pathways because incorrect guidance about attendance, evaluation, or regulations can cause serious confusion.

The third challenge is **semantic mismatch between user language and document language**. Students may ask "What is the minimum attendance rule?" while the official document uses phrases such as "eligible to appear for the End Semester Examination" or "condonation of shortage of attendance". Exact keyword matching alone may miss such variation. Dense retrieval helps bridge semantic mismatch, but lexical specificity remains important for formal terms. Hence, a hybrid search strategy becomes necessary.

The fourth challenge is **entity and relation handling**. Queries about "who teaches", "who is the HOD", or "which department" are fundamentally relational. Document retrieval may return passages that mention the relevant entities but still require inference or may fail entirely when the answer is stored structurally rather than narratively. Knowledge graphs solve this partially, but standalone graph systems usually do not provide rich explanatory prose. Existing systems that commit to only one representation therefore remain incomplete.

The fifth challenge is **maintainability and update management**. Institutional knowledge changes over time. New faculty assignments, revised regulations, and updated seminar instructions must be incorporated without rebuilding the entire system from scratch. A usable academic assistant should allow document uploads, graph updates, validation checks, and index rebuilding. If updates are cumbersome, the system quickly becomes outdated and untrustworthy.

The sixth challenge is **local deployment constraints**. Educational institutions may not always have the budget or policy freedom to rely on commercial APIs. A practical solution must therefore function with locally hosted or offline-friendly components. This imposes design constraints related to model size, startup reliability, local cache usage, and service orchestration. The NexRag codebase explicitly reflects this challenge by preferring locally cached models and local services.

The seventh challenge is **evaluation complexity**. Measuring the performance of hybrid RAG systems is not straightforward because answer quality depends on retrieval quality, grounding faithfulness, source relevance, and response clarity. Frameworks such as RAGAs have been proposed to address this multifaceted evaluation problem (Es et al., 2024). For an academic assistant, both functional correctness and operational readiness matter. Therefore, evaluation must consider module loading, routing behavior, retrieval quality, graph connectivity, answer transparency, and user interface support rather than relying on a single metric alone.

## 1.6 Objectives of the Project

The main objective of the project is to develop a robust, local-first hybrid academic assistant capable of answering institutional queries using both a knowledge graph and a retrieval-augmented document search pipeline. This broad objective is pursued through several specific objectives that shape the design and implementation of NexRag.

The first objective is to create a structured **knowledge graph layer** capable of representing institutional entities such as departments, faculty members, courses, and regulations, along with their relationships. This layer must support precise querying through SPARQL and enable entity-centric questions to be answered directly whenever structured evidence exists.

The second objective is to build a **document ingestion and retrieval pipeline** for academic PDFs. This includes extracting text from uploaded documents, chunking the extracted text into retrieval-friendly units, encoding those chunks into dense embeddings, indexing them in FAISS, and maintaining corresponding metadata for source-aware retrieval. The pipeline should also support lexical BM25 ranking to complement semantic search.

The third objective is to implement a **query routing mechanism** that identifies user intent and decides whether a question should be answered through the knowledge graph, the document retrieval engine, or a combined mode. This objective is important because it prevents a one-size-fits-all processing strategy and makes the response pipeline more context-aware.

The fourth objective is to enhance retrieval precision through **reranking and evidence filtering**. By applying a cross-encoder based reranker and threshold-based gating, the system should reduce noisy retrieval outputs and provide only sufficiently relevant context to the generator. This contributes directly to answer quality and trustworthiness.

The fifth objective is to use a **local language model** to generate coherent grounded answers while preserving transparency. The final response should not be detached from evidence; instead, it should reflect whether the answer originated from the knowledge graph, from retrieved documents, or from both. The system should also expose sources, routing mode, and confidence indicators to the user.

The sixth objective is to design a **user-friendly interface** through which users can submit queries, view streaming responses, inspect supporting sources, monitor system status, and edit knowledge graph files when needed. This objective recognizes that usability and explainability are as important as algorithmic accuracy in real deployments.

The seventh objective is to support **maintainability and future extensibility** by including automation for startup, logging, health checks, indexing workflows, and evaluation scripts. A final year project should ideally demonstrate not only the central algorithm but also the surrounding engineering practices needed to keep the system functional over time.

## 1.7 Scope and Delimitations

The scope of NexRag covers academic query answering within a bounded institutional environment. The current system is designed for educational and departmental use, with knowledge sources consisting of PDF documents and RDF/Turtle files that represent institutional information. The implemented query classes include definitions, regulations, course-related questions, faculty information queries, and general academic assistance. The system supports document upload, vector index rebuilding, basic conversational continuity through short history passing, and limited knowledge graph maintenance through source editing and validation.

The scope also includes local-first deployment and evidence-oriented interaction. Unlike cloud-dependent assistants, NexRag is intended to operate using locally available infrastructure: a local backend API, a local frontend, a locally hosted Fuseki endpoint, local vector index files, and a local language model served through Ollama. This makes the system suitable for laboratories, institutional intranets, or privacy-sensitive environments where internet dependence or external API usage may be undesirable.

However, the project has deliberate delimitations. It is not intended to function as a universal academic search engine across all institutions or all forms of educational content. Its effectiveness depends on the quality and coverage of the documents and graph data indexed into the system. The current router uses rule-based intent classification rather than a learned classifier, which limits linguistic flexibility in ambiguous cases. The present knowledge graph schema is intentionally compact and institution-focused, not a full semantic model of all academic administration. Furthermore, while the frontend and backend support operational use, the evaluation observed for this report is bounded by the available repository artifacts and local runtime conditions on the verification date.

The report also distinguishes between **implemented features** and **runtime availability during testing**. For example, the knowledge graph module is implemented and query functions are present, but the Fuseki service was not active during the verification session documented in Chapter 4. Similarly, the frontend build was blocked by sandbox process restrictions during verification, which is reported transparently as an execution environment issue. These delimitations are important because they preserve the integrity of the technical discussion and prevent overstating experimental outcomes.
